1. What the boundary is
-----------------------
src/lib/window-source.ts holds one interface and one implementation.

  WindowSource = { region, windowsFor({ date, crops }) }
  WindowSourceResult = { season, windows, empty }

  brazilWindowSource(place, snapshot) is the only implementation. It calls
  seasonForDate(date) for the derived Y/YY label and buildSeasonBand for the rows, so the
  Y/YY to Y/YYYY normalisation stays inside the Brazil source and uses the one documented
  mapping (snapshotSeasonKey of src/lib/timeline.ts, reused by src/lib/season-band.ts).

  windowSourceFor(location, snapshot) selects the source of the field's region and returns
  null when that region has none. Block 4 reads the region from the field's location text,
  where a Brazilian field names its state; the United States source is OD-23, owned by
  block 7, and block 5 supplies the active regionId.

src/components/SeasonBand.tsx draws what the source answers. Three states, kept apart:
  no field selected        -> the band renders nothing (R-35, unchanged from wave 3)
  source for the region    -> the windows and empty texts of wave 3, unchanged for Brazil
  no source for the region -> no window, one empty text naming the reason
