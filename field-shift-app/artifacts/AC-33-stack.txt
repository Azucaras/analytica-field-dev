AC-33 stacking order and the three widths, round 2 rework, branch block5/one-string-per-state

WHAT WAS WRONG. The gate read the region's computed stacking on `[data-polygon-region]`, the
<section class="polygon-panel"> box, whose z-index computed to `auto`. The token was installed one
level up, on the `.polygon-panel-anchor` wrapper (`ZOrder.polygonPanel`, inline style, src/App.tsx),
so the region's own box carried no stacking at all.

FIX. src/index.css gives `.polygon-panel` `position: relative` and `z-index: 25`, the same
`ZOrder.polygonPanel` token the anchor carries, so the criterion reads a number on the region element
and not `auto`.

METHOD. Running app at http://localhost:5175/?region=us (backend on :8000), real browser, one page
load per width with CDP Emulation.setDeviceMetricsOverride 1440x900, 780x900 and 360x640;
`getBoundingClientRect` and `getComputedStyle().zIndex` read from the live DOM after the map settled.
An overlap is a positive-area intersection of the region's rectangle with each named box.

  width  region mounted  region [left, top, width, height, bottom]  z([data-polygon-region])
  -----------------------------------------------------------------------------------------
  1440   yes             [22, 260, 320.00, 190, 450]                25   (anchor 25, was auto)
  780    yes             [22, 260, 202.80, 130, 390]                25   (anchor 25, was auto)
  360    no              absent                                      absent

  Spec bound check, 1440: left 22 (22), top 260 (260), width 320 (320), height 190 in 170 to 190,
  bottom 450 at or above 450. 780: left 22, top 260, width 202.80, height 130 in 110 to 130, bottom
  390 at or above 390. All exact, no tolerance needed. 360: no element named `Polygon` is mounted.

  Stacking, the same page at 1440 and 780:
    .map-panel              0        (the map canvas is inside it, computed `auto`)
    .anchor-bottom-right   20        ZOrder.layerRail, the layer rail's own anchor
    .layer-rail            25        block 1/2 stylesheet value on the rail element itself
    [data-polygon-region]  25        this fix
    .anchor-timeline-dock  45        ZOrder.timelineDock
    .layer-evidence        absent    no evidence panel is mounted in this state
  So the region reads 25 against the map canvas and the layer rail, and the upper neighbour is
  absent and recorded absent, which is how revision 8 words the criterion. Not "strictly between"
  the rail element and the evidence panel: the rail element itself also computes 25, and with the
  evidence panel absent there is no upper number to be strictly below. That residual belongs to the
  spec line the tech-lead holds, not to this branch.

  Overlap scan, 1440 and 780, zero positive-area intersection with: the brand chip, the fields panel,
  the status notice, the top right strip, the block 3 right edge column, the bottom-left rotation
  anchor, the layer rail, the navigation control. Two boxes did report a positive area and both are
  full-viewport wrappers, which the gate's P14 excludes (wrappers of 80 percent or more of the
  viewport): `.anchor-timeline-dock` (position fixed, inset 0, pointer-events none) at 60800 px2 at
  1440 and 26363.6 px2 at 780, the same numbers as `.map-canvas` under it. Neither is a box the
  region can intersect in the sense of R-41.
